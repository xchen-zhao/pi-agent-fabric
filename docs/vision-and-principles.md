# 愿景与原则

## North Star

> 打造一个让全球开发者信赖、赞叹并愿意共同参与的，开源、本地优先、厂商中立、可靠可恢复的 AI Agent 编排基础设施。让任何开发者都能在一个统一控制平面中，安全、透明、高效地协调不同 Agent，使它们真正实现 1+1>2。

> Build the open, local-first, vendor-neutral orchestration fabric that developers trust to coordinate any AI agent—safely, transparently, and reliably.

## 必须始终坚持的原则

1. **不是制造另一个 Agent，而是让所有 Agent 更好地协作。**
2. **不绑定任何厂商、模型、CLI 或云平台。**
3. **本地优先，用户拥有代码、数据、任务和运行历史。**
4. **可靠性优先于炫技，失败必须可恢复。**
5. **不知道就是不知道，不伪造额度、成本和确定性。**
6. **每一次调度都应当可解释。**
7. **安全、隔离和权限边界不是后期功能。**
8. **核心保持精简，能力通过 Adapter 和插件生态扩展。**
9. **用不同 Agent 的差异创造协同价值，而不是重复消耗。**
10. **做全球开发者真正愿意用于日常工作的基础设施，而不只是 Demo。**
11. **每次工作都必须复盘，开发完成必须回头审查、整理并完整复测。持续改进是工程流程的一部分，不是可选仪式。**

## 成功标准

我们不以“接入了多少 Agent”衡量成功，而以以下问题衡量：

- 开发者是否敢把重要任务交给它？
- 开发者是否能理解它为什么选择某个 Agent、模型和执行方式？
- 执行过程是否安全、透明、可审计？
- 任务在崩溃、退出、限流或额度不足后是否能够可靠恢复？
- 多个 Agent 是否通过专业分工和交叉验证产生了真实协同，而不是重复消耗？

## 决策过滤器

每个功能、依赖和架构决策都必须回答：

> 它是否让异构 Agent 的协作变得更开放、更可靠、更透明、更安全？

如果答案是否定的，就不应仅仅因为“看起来很酷”而加入。

每个开发批次结束前执行：

```text
实现
  → 审查 diff 与错误路径
  → 整理代码和文档
  → 类型检查与完整复测
  → 记录复盘、风险和下一步
```

发生目标冲突时，优先级为：

```text
安全与用户控制
  > 正确性与可恢复性
  > 透明度与可解释性
  > 开放性与互操作性
  > 性能与成本
  > 功能数量与视觉效果
```
