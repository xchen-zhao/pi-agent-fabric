# V1.1 Runtime Hardening 复盘

日期：2026-07-22

## 完成范围

- Grok Prompt 从进程参数迁移到权限为 `0600` 的临时文件，并在所有正常结束路径清理。
- 评估 Kimi ACP：确认 ACP 可改善协议权限，但不能替代 OS 只读隔离，因此 Kimi 继续禁用。
- 增加 SQLite Usage Ledger，记录运行、Usage、成本、错误与 Quota Signal，不记录 Prompt、输出正文和工作区路径。
- 新增 `fabric usage`、`/fabric-usage` 与自定义 Ledger 路径。
- 增加认证、限流、Retry-After、账期额度耗尽错误分类测试。
- 增加 Pi 工具生命周期事件归一化。

## 审查中发现并修正

1. CLI 集成测试曾写入默认用户 Ledger：增加 `PI_AGENT_FABRIC_LEDGER_PATH`，测试统一使用内存数据库，并删除被测试污染的本地数据库。
2. 临时 Prompt 文件在日志初始化失败时可能残留：日志初始化和临时目录清理改为统一失败路径。
3. Audit Log Stream 缺少错误监听，极端情况下可能造成未处理异常：增加错误捕获与 `audit-log-failed` 分类。
4. 自定义 Ledger 初始化失败时数据库句柄可能未关闭：增加失败关闭逻辑。
5. 原始错误分类没有提取 Retry-After：增加秒、毫秒和分钟单位解析。

## 复测结果

- TypeScript 严格类型检查通过。
- 38 项自动化测试全部通过。
- Grok 临时 Prompt File 通过真实端到端只读复测，返回 `OK`；该必要复测报告输入 3309、缓存读取 10112、输出 29 Tokens，报告成本 `$0.0098256`。
- Usage Ledger CLI 使用隔离数据库完成端到端复测；Kimi 在进程启动前失败记录正确。
- Pi Extension 离线加载通过。
- `npm audit --omit=dev`：0 个运行时漏洞。
- 敏感信息扫描未发现本机路径、认证信息或真实 Smoke Session ID 被纳入仓库。

## 遗留风险

- Kimi 需要 ACP 权限层与 OS 沙箱双重保护，尚未实现。
- 临时目录在宿主进程被 `SIGKILL` 或机器断电时可能残留，需要后续启动清理策略。
- Claude、Codex、Grok 的工具生命周期事件尚未使用真实 Fixture 覆盖；不应仅凭推测实现。
- Usage Ledger 只记录经过 Agent Fabric 的调用，不能代表供应商完整账单或精确剩余额度。
- Ledger 尚无保留期、导出和删除命令。
- 开发依赖中的 `protobufjs` moderate 公告仍等待 Pi 上游升级；运行时审计为 0。

## 下一步

进入 V1.2 可用性路由前，先定义 Runtime Health Snapshot，并以真实错误与 Ledger 事实为输入；不得把 `unknown` 转换为虚假可用额度。
